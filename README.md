# Videoroom — мультиракурс для YouTube (MVP)

Chrome-расширение: объединяет видео одного события, снятые разными людьми с
разных точек, и даёт переключаться между ракурсами с сохранением момента
времени.

## Установка

1. Откройте `chrome://extensions`, включите **Режим разработчика**.
2. **Загрузить распакованное расширение** → выберите папку `D:\ClaudeVideoroom`.
3. После правок кода нажмите ⟳ у расширения и перезагрузите вкладку YouTube.

## Как пользоваться

1. Откройте любое видео события на YouTube → иконка расширения → **Создать комнату**.
2. Добавьте ссылки на другие ракурсы (можно вставить пачкой, по одной на строку).
3. Под плеером появится полоса ракурсов. Нажмите **🎚 Синхронизировать по звуку**:
   расширение прослушает все ракурсы на 8× (без звука для вас) и само подберёт
   сдвиги. Для 4 видео по ~18 мин это ~8 минут. Прослушанные видео кешируются,
   так что новый ракурс потом досинхронизируется быстро.
   Подгонять вручную можно в кинозале: кнопки ±0.1 или клавиши `[` `]`.
4. В кинозале (🎬) нажмите ✎ на карте под видео и расставьте камеры так, как они
   стояли в зале (сцена сверху). Тогда WASD будут ходить по залу.

### Поиск ракурсов и общие комнаты

- **🔍 Найти ракурсы.** Кнопка в полосе комнаты, а под видео без комнаты есть
  компактная плашка (отключается в ⚙). Кандидаты берутся из трёх источников:
  поиск YouTube по 3 запросам, похожие видео и повторный поиск от лучших
  найденных. Ранжирование учитывает:
  - совпадение слов в названии;
  - соперников «X vs Y», стадию (полуфинал/финал…), дисциплину (hip hop/popping…)
    и год. Если у исходного видео их нет, они берутся у уверенных совпадений;
  - точную дату загрузки.

  Противоречащие кандидаты уходят в блок «Сомнительно». Качество замеряет
  `node tools/eval-search.js` (KOD 2016: 12/12 ракурсов в топ-10, 0 чужих;
  до доработки было 8/12 и 13 чужих).
- **🎧 Проверить звуком.** Исходное видео прослушивается целиком (8×), у каждого
  кандидата — до трёх минутных фрагментов (16×). Если два фрагмента дают один
  и тот же сдвиг (±0.5 с), ракурс подтверждён (✓) и добавляется сразу с этим
  сдвигом. Случайное совпадение бывает примерно раз на 2000 пар. Одиночный
  фрагмент ненадёжен: на ритмичной музыке чужие видео дают такие же пики.
- **🌐 Общие комнаты.** Если у видео нет вашей комнаты, расширение ищет его в
  публичном реестре [Beetlejuice8921/videoroom-rooms](https://github.com/Beetlejuice8921/videoroom-rooms)
  и показывает найденную комнату с пометкой 🌐. Ваши правки (сдвиги, карта)
  сохраняются как личная копия.
- **Поделиться.** В меню у комнаты есть кнопка 🌐: откроется заявка на GitHub с JSON
  комнаты. GitHub Action реестра проверит её (2–12 ракурсов, видео не заняты
  другими комнатами, менять комнату может только автор) и добавит в
  `index.json`. Расширения подхватывают реестр раз в 30 минут.

**Готовый пример:** `examples/kod2016-semifinal-france-china.json`. Это 4 ракурса
одного баттла, сдвиги найдены по звуку (точность около 0.1 с). Откройте окно
расширения → «Импорт», вставьте содержимое файла.

### Два режима просмотра

| | На странице YouTube | Кинозал |
|---|---|---|
| Где | обычная страница видео | отдельная вкладка на GitHub Pages (кнопка 🎬) |
| Как переключается | в родном плеере (`loadVideoById`) | все ближайшие ракурсы уже играют в фоне |
| Задержка | ~0.6–1 с, с превью-заглушкой | **мгновенно** (тёплый) / ~2.5 с (холодный) |
| Звук | вместе с ракурсом | непрерывный из камеры 1 или из активного ракурса |

### Клавиши

- `1`–`9` — ракурс по номеру, `Q` / `E` — предыдущий / следующий
- `W` / `S` — камера ближе к сцене / дальше, `A` / `D` — левее / правее по карте.
  Пока камеры не расставлены, они стоят дугой в порядке списка, и `A`/`D` = предыдущая/следующая
- Кинозал: `Пробел`/`K` — пауза, `←`/`→` — 5 с, `J`/`L` — 10 с, `[` `]` — сдвиг
  активного ракурса ±0.1 с, `M` — звук, `F` — полный экран

Цифры, которых больше, чем ракурсов, остаются за YouTube (перемотка на N0%).

## Устройство

```
manifest.json
src/background.js          открывает кинозал во вкладке
src/content/cinema-bridge.js на странице кинозала: доступ к комнатам расширения
tools/publish-cinema.sh    публикация кинозала на GitHub Pages
src/content/page-bridge.js MAIN world: доступ к API плеера (#movie_player)
src/content/content.js     полоса ракурсов и переключение на youtube.com
src/content/audio-sync.js  синхронизация по звуку: захват огибающих и корреляция
src/content/angle-search.js поиск других ракурсов в поиске YouTube
src/shared/venue-map.*     мини-карта площадки (общая для YouTube и кинозала)
registry/                  код реестра общих комнат (Action + проверка заявок)
tools/publish-registry.sh  публикация кода реестра на GitHub
src/shared/rooms.js        модель комнаты, хранилище, ссылка на кинозал
src/shared/embed-player.js управление YouTube embed через postMessage
src/room/                  кинозал: тёплый пул, общие часы, синхронизация, карта
src/popup/                 создание и редактирование комнат, импорт/экспорт
```

**Синхронизация.** У каждого ракурса есть `offset`, общая шкала
`timeline = videoTime + offset`. В кинозале часы шкалы следуют за активным
ракурсом, остальные плееры подтягиваются к часам (seek при расхождении больше
0.3 с у активного и 0.2 с у фоновых, с паузой между коррекциями).

**Синхронизация по звуку.** Видео проигрывается в плеере YouTube на 8×, звук
снимается через Web Audio (зрителю идёт тишина), из него строится огибающая
громкости с шагом 0.1 с. Медленный тренд вычитается, остаются удары, крики и
аплодисменты. Все пары сравниваются взаимной корреляцией (FFT), затем ракурсы
связываются по самым уверенным парам от камеры 1. Пара принимается, если пик
хотя бы в 1.3 раза выше лучшего пика в стороне. Огибающая кешируется в
`chrome.storage.local` (~14 КБ на 18 мин).

**Пул в кинозале:** активный + источник звука + наведённый курсором + соседние
(до 4 embed). Фоновые играют без звука в маленьком невидимом слое, поэтому
переключение — просто crossfade.

## Что выяснилось при проверке

- **YouTube не воспроизводит embed-плееры внутри страниц youtube.com**
  (ошибка 152, без referrer — 153). Поэтому мгновенное переключение
  живёт в отдельном кинозале, а на самой странице YouTube ракурс
  переключается в родном плеере.
- Переключение в родном плеере: 0.6–1.3 с. Расширение запоминает
  фактическую задержку и стартует новый ракурс с упреждением, а после загрузки
  досинхронизирует позицию, если промах больше 0.4 с.
- В кинозале на тестовых видео: тёплое переключение ≈ 0 мс, расхождение
  ракурсов в пределах 0.01–0.17 с.
- Chrome ставит на паузу беззвучные видео в **фоновых вкладках**. Пока
  вкладка кинозала не на переднем плане, фоновые ракурсы будут
  подтормаживать; на активной вкладке этого нет.

### Где живёт кинозал

YouTube не принимает и страницы расширения (`chrome-extension://`, ошибка 153),
поэтому кинозал размещён на GitHub Pages:
<https://beetlejuice8921.github.io/videoroom-cinema/room/room.html>
(репозиторий `Beetlejuice8921/videoroom-cinema`, в нём только `src/room` и `src/shared`).

- Комната передаётся в адресе (`#data=…`). На сервер ничего не отправляется.
- Сдвиги сохраняются через `src/content/cinema-bridge.js`: content script
  расширения на этом домене пересылает чтение и запись комнаты в
  `chrome.storage`. Без установленного расширения кинозал работает, но не сохраняет сдвиги.
- Обновить кинозал после правок в `src/room` или `src/shared`:
  `bash tools/publish-cinema.sh` (нужен авторизованный `gh`).
- Свою копию на другом хостинге можно указать в настройках (⚙ в popup).

В кинозале фоновые ракурсы подтягиваются к часам при расхождении больше 0.2 с.
Каждый плеер сам выучивает задержку seek (обычно ~0.8 с), поэтому через
несколько секунд после старта все ракурсы идут в пределах ~0.06 с.

## Ограничения MVP

- Личные комнаты хранятся локально (`chrome.storage.local`). Поделиться можно
  через общий реестр (🌐) или «Экспорт» / «Импорт» JSON.
- Видео, у которых автор запретил встраивание, в кинозале открываются
  отдельной вкладкой YouTube; на странице YouTube они работают.
- На YouTube после переключения адрес страницы, название и комментарии
  остаются от исходного видео.
- Во время рекламы переключение недоступно.
